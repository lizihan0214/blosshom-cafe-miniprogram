# 桌码点单与自动出单方案

## 推荐落地方式

门店现有设备为 **芯烨 XP-A160H**：80mm、160mm/s、网口、ESC/POS。首版优先继续使用这台机器，不必为了桌码点单立即换机。它属于局域网票据打印机，不是直接接收公网订单的云打印机，因此需要收银电脑或低功耗小主机常开，运行本地打印桥接服务。

XP-A160H 的 80mm 纸宽和 160mm/s 速度足够 12 桌、单收银机使用。相比约 58mm 机型，80mm 小票能更自然地容纳中英文商品名、规格、备注、桌号和门店信息。若以后不想保留常开的收银电脑，再升级到 **XP-N260L 云打印机**；该型号支持本地/云端打印、自动切刀、语音提醒以及网口/Wi-Fi/4G组合。

```text
桌牌小程序码（t=08）
  → 点单页读取并暂存桌号
  → createPayment 云端计价并保存 tableNo
  → 微信支付
  → paymentNotify 验签、解密并确认 PAID
  → 创建唯一 print_jobs/{orderNo}
  → 收银电脑上的 print-bridge 领取任务
  → 通过局域网 ESC/POS 发送到 XP-A160H
  → 收银台打印机自动出单
```

只有微信支付回调或云端查单确认 `PAID` 后才能创建打印任务，不能依据 `wx.requestPayment` 的前端成功回调打印。

## 桌牌二维码

当前按 12 张桌建立 `01–12` 桌号。生成微信小程序码时：

- 页面：`pages/menu/index`
- scene：`t=01`（每张桌子替换对应桌号）
- 二维码下方同时印刷可读文字，例如“08 桌｜扫码点单”
- 二维码文件与桌号建立台账，打印前逐张扫码验收，避免贴错桌

当前前端支持直接参数 `?table=08`，也支持小程序码 scene `t=08`。桌号上下文保存 6 小时，结算页会再次显示并允许顾客核对。

正式批量生成小程序码应在受控云函数或管理员脚本中完成。AppSecret 只能放在云端密钥配置中，不得写入小程序、仓库、二维码文件名或普通操作文档。

项目已提供 `scripts/generate-table-qrcodes.js`，一次生成 `01–12` 共 12 张 PNG。小程序还未正式发布时先生成体验版：

```powershell
$env:WECHAT_APPID = "wx9911d30b35ffc8b1"
$env:WECHAT_APPSECRET = Read-Host "请输入 AppSecret" -MaskInput
npm run qrcode:tables -- --env=trial
Remove-Item Env:WECHAT_APPSECRET
```

小程序审核发布后生成最终桌牌码：

```powershell
$env:WECHAT_APPID = "wx9911d30b35ffc8b1"
$env:WECHAT_APPSECRET = Read-Host "请输入 AppSecret" -MaskInput
npm run qrcode:tables -- --env=release
Remove-Item Env:WECHAT_APPSECRET
```

图片输出到 `artifacts/table-qrcodes/`，文件名包含桌号和环境，例如 `table-08-release.png`。该目录已加入 `.gitignore`。生成后先逐张扫码确认页面顶部和结算页显示的桌号一致，再交给广告店制作桌牌。

## 打印任务数据

建议新增私有集合 `print_jobs`，客户端读写权限均关闭：

```js
{
  _id: orderNo,
  orderNo,
  status: 'PENDING', // PENDING | SENDING | PRINTED | FAILED
  printerId: 'cashier-01',
  attempts: 0,
  vendorOrderId: '',
  lastErrorCode: '',
  nextRetryAt: Date,
  createdAt: Date,
  printedAt: Date
}
```

`_id` 直接使用业务订单号，保证重复支付通知不会创建多张打印任务。发送结果不明确时，先调用厂商的查单接口确认，再决定是否重试，避免网络超时导致重复出单。失败任务保留并告警，收银员可以执行“补打”，但补打必须留下次数和操作记录。

## 小票内容

XP-A160H 的 80mm 小票按以下优先级排版：

1. 顶部用最大字号打印 `08 桌` 或 `外带`。
2. 取餐码、下单时间、订单号后 8 位。
3. 商品中文名、规格、数量和单项小计。
4. 顾客备注使用醒目分隔线，空备注不打印。
5. 合计金额与支付状态。
6. 底部打印门店名，不打印完整手机号和 OpenID。

堂食小票应把桌号放在第一视觉层级，取餐码作为核对码；外带小票则把取餐码放在第一视觉层级。

## 云函数与密钥

现有 XP-A160H 方案建议增加两个独立组件：

- 云函数 `claimPrintJob`：验证门店打印设备身份，原子领取一条待打印任务。
- 收银电脑服务 `print-bridge`：只发起出站 HTTPS 请求领取任务，再通过局域网把 ESC/POS 数据发送给打印机。

打印桥接凭据放入 Windows 凭据管理器或服务环境，不写进源码。CloudBase 侧只保存凭据摘要。不要把打印机端口映射到公网，也不要在路由器上开放打印机端口。

云端只保存以下环境变量：

- 打印桥设备 ID
- 打印桥令牌摘要或验签公钥
- 单店打印机逻辑 ID

这些参数不能放入 `src/`、`cloudbaserc.json`、Git、前端请求或日志。支付回调函数只写打印任务；本地桥接负责 ESC/POS 和打印机适配。这样以后更换成芯烨云打印机时，不需要修改支付主流程。

为处理短暂断网，桥接服务调用失败后把任务保留为 `FAILED`，每 10–30 秒重试到期任务。重试必须有上限和退避策略；打印机离线、缺纸应在收银电脑产生明显告警。打印机建议在路由器中绑定固定 IP，桥接程序只连接该内网 IP。

## 上线顺序

1. XP-A160H 接入门店路由器，在路由器 DHCP 设置中为它保留固定 IP。
2. 提供桌号清单、出单份数和小票样式。
3. 在收银电脑安装芯烨官方 80 系列驱动并完成 Windows 测试页打印。
4. 安装门店 `print-bridge` 服务，并把设备令牌写入 Windows 凭据管理器或服务环境。
5. 创建 `print_jobs` 集合、索引和禁止客户端读写的安全规则。
6. 部署领取任务云函数和桥接服务，先打印不含真实顾客信息的测试小票。
7. 用 0.01/0.10 元测试商品完成“扫码—支付—自动打印”闭环。
8. 测试重复回调、打印机断网、缺纸、恢复联网和人工补打。
9. 全部桌牌逐张扫码核对后再投入营业。

## 下一步所需资料

- 如实际桌牌不是 `01–12`，提供最终桌号对应关系
- XP-A160H 接入路由器后显示的固定内网 IP
- 收银电脑是否能在营业期间保持开机联网
- 收银台一联还是收银台与后厨各一联
- 小票上要显示的门店正式名称、电话和地址
- 是否需要后厨分单（咖啡、厨房、吧台分别打印）

确认打印机内网 IP 和收银电脑运行条件后，实现 `claimPrintJob + print-bridge`。打印适配保持独立，不写进支付回调。
